# 第二阶段：选择三段报告计划 `paired-report-plan-v0.1`

输入仅包含服务端已验证的事实账本、关系、真实未定事项、允许的模板目录，以及账本、目录和模板各自的 SHA-256。不得再次读取原始回答或历史记录。中间计划仅在服务端内存中使用，不给双方、AI 输入框或手记。

> 只输出符合 `report-plan.schema.json` 的 JSON。三个 SHA-256 均原样返回。只选输入中存在且获服务端允许的关系 ID、未定事项 ID、行动模板和注意点模板；不输出自由文本、不补事实。
>
> `commonAndDifferences` 至少选一条 `shared` 或 `compatible` 关系；账本有具体差异时选有据的 `different` 关系，没有时 `differentRelationIds=[]`，由服务端固定句说明。`compatible` 必须按 A、B 分别叙述，不能渲染为“双方都”。
>
> `adviceForBoth` 只选值得讨论的已验证议题和最多两条固定注意点。不能选择要求一方解释、说服、让步或继续靠近的内容。
>
> `nextSteps` 只选 1–2 个有来源支持、双方愿意时才尝试且可随时停止的行动；可选最多两条已验证的边界事实 ID，但渲染时必须保留该事实的当事人与触发条件。只选账本中真实存在的 `openItemIds`；空数组是有效结果，不能为了写“待确认”而制造问题。已经由双方同义回答说清的安排不得以未知形式出现。

服务端校验计划与账本哈希、ID、模板前提和状态后，**由服务端固定模板渲染**“共同点与差异”“给你们的建议”“接下来的建议”三个自然段，输出仍为现有 `paired-report-v0.2` 公共契约。模型不能直接写或修改最终正文。每段只保留服务端内部证据 ID，显示、导出、AI 草稿和手记草稿均不附来源编号。模板不足、段落超 220 字或没有有据的双方共同或相容关系时返回 `insufficient`；安全规则优先。
