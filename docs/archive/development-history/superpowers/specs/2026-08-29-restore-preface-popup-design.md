# 恢复“欢迎来到内界 CAVE”阅读弹窗设计

## 目标

恢复首次旅程原有的两阶段前言体验：

`开启旅程 → 18+ 本机声明 → 选择称呼 → 欢迎来到内界 CAVE 阅读弹窗 → 我已了解，开始旅程 → 正式旅程第一页`

本次只恢复称呼选择与正式内容之间丢失的阅读弹窗，不改变成年声明、公共四栏导航、认证、日志、私密数据库或正式六页内容。

## 根因

当前 `PrefaceRoute` 把两个独立状态合并在一次操作中：用户点击“这样称呼我”后，代码连续保存 `addressPreference` 与 `prefaceRead=true`，随后直接进入 `/journey/body-knowledge`。因此系统没有机会显示独立阅读弹窗，也无法区分“称呼已保存”和“短笺已阅读”。

## 交互设计

### 称呼阶段

- 保留现有“你 / 妳”选择卡与“这样称呼我”按钮。
- 点击按钮只保存 `addressPreference`，不写入 `prefaceRead`。
- 保存成功后，在当前 `/journey/preface` 路由打开阅读弹窗。
- 保存失败时留在称呼阶段，沿用现有错误反馈与重试行为。

### 阅读弹窗阶段

- 使用项目现有 `BottomSheet`，标题为“欢迎来到内界 CAVE”。
- 正文恢复产品蓝图中的四段开始前短笺，并根据已保存称呼显示“你”或“妳”。
- 弹窗内容区域可滚动，适配小屏和放大字体。
- 只有一个主操作：“我已了解，开始旅程”；不提供跳过入口。
- 点击主操作后才保存 `prefaceRead=true`；保存成功后进入 `/journey/body-knowledge`。
- 保存失败时弹窗保持打开，显示可重试错误，不进入正式内容。

## 恢复与路由行为

- `ageConfirmed !== true`：继续 fail-closed 到 `/journey/welcome`，不显示称呼或弹窗。
- `addressPreference === null`：显示称呼阶段。
- 已有称呼且 `prefaceRead === false`：直接打开阅读弹窗；App 在弹窗阶段关闭后可以恢复到该阶段。
- 已有称呼且 `prefaceRead === true`：直接进入 `/journey/body-knowledge`，不重复展示弹窗。
- 主按钮的异步状态防止重复提交；任何持久化失败都不得提前改变下一步路由。

## 组件边界

- `PrefaceRoute` 负责根据持久化快照选择称呼、弹窗或继续路由，并按顺序调用运行时服务。
- `PrefacePage` 只负责称呼选择，不再暗含“短笺已读”。
- 新增独立的阅读弹窗组件，负责长文、称呼替换、确认按钮和错误状态；组件不直接依赖路由或仓库。
- 复用现有 `BottomSheet` 与 `JourneyAction`，不新增路由或数据库字段。

## 测试与验收

- 组件测试覆盖标题、完整四段正文、称呼替换、唯一主操作以及提交失败后可重试。
- 路由测试证明保存称呼时只写 `set-address-preference`，不会写 `set-preface-read` 或进入正文。
- 路由测试证明快照刷新后弹窗出现；点击确认才写 `set-preface-read` 并进入正文。
- 路由测试覆盖“已有称呼但未读”直接恢复弹窗，以及“已读”直接进入正文。
- 既有未成年深链保护、成年声明、旅程导航与私密数据边界测试保持通过。
- 完成后运行移动端定向测试、全量测试、TypeScript 与 ESLint。

## 不在范围

- 不调整首页品牌布局、底部导航或 18+ 文案。
- 不增加“先跳过”、关闭后继续正式内容或新的完成标记。
- 不合并主工作区中尚未提交的 auth/journal 工作。
