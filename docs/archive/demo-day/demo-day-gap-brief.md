# 内界 CAVE｜当前能力与赛前缺口

> 版本：讨论稿 v0.1｜原则：只写可验证状态，不把计划当成果。

## 已经可以成立的产品能力

- 成年确认、称呼偏好和六页本地旅程。
- 身体与安全知识、过夜期待、行为地图、关系反思。
- 明确标注为非 AI 的预设沟通练习，包含暂停、撤回和安全分支。
- 私密准备清单与可编辑、可复制、可保存图片的沟通卡。
- 回顾、版本历史、从旧回顾分支、单条删除和全部本机数据删除。
- 移动端本地优先架构，以及独立开发但尚未接入移动端的 AI gateway。

## Demo Day 前真正影响评分的缺口

| 优先级 | 缺口 | 当前建议 |

| P0 | 目前只有 Expo Go，没有脱离开发电脑的真机安装证据 | 把 Expo Go 明确称为现场原型；准备固定电脑、热点、备用设备和完整离线录屏 |
| P0 | 医学、性健康和部分安全内容只有内部审核，生产校验仍会拦截 | 公开演示只走低风险路径；隐藏医学图，不声称专家背书，不修改审核状态冒充通过 |

| P1 | 现场流程尚未验证能稳定压进 3 分钟 | 固定一条黄金路径，连续排练并准备 20 秒、90 秒和 3 分钟版本 |

## 这次主动不做的事

- 不在赛前临时把 AI gateway 接入高敏感主流程。
- 不为了让生产校验变绿而把内部审核改写成专家审核。
- 不增加 Demo 专用代码或快速重置功能。
- 不承诺 TestFlight、App Store、云同步或正式运营指标。

## 评委可能追问的诚实回答

**为什么不用 AI？** 这一版优先帮助用户形成自己的判断，而不是让模型替她判断。gateway 是独立研发探索，但尚未进入正式用户路径。

**内容经过医学审核了吗？** 尚未完成合格专家审核。公开演示会避开待审医学内容，也不会把产品描述成医学建议。

**为什么强调本地优先？** 用户会记录关系边界和私密表达，默认不上传比“以后再补隐私”更符合这个场景。Expo Go 原型不等于已完成真机加密验证。

**是不是二次开发？** 以仓库根提交、活动期提交记录和最终 Demo SHA 证明本次创作期内的 0→1 增量，不用口头宣称代替证据。
