# 首次启动公共 Tabs 与首页单屏设计

> 本文覆盖旧文档中“首次旅程完成后才解锁长期 Tabs”的路由规则；成年门禁与正式旅程顺序仍以现行六页规格为准。

## 目标

恢复 CAVE 原有的公共底部导航：用户首次打开 App、尚未完成首次旅程时，也能看到并正常使用“首页 / 回顾 / 练习 / 我的”四个入口。同时让首次首页在常见小屏、默认字号下无需滚动即可看到“开启旅程”。

## 导航架构

- `(tabs)` 是从首次启动开始就可用的公共主框架，不再以“首次旅程已完成”作为进入条件。
- 根路由始终进入 `(tabs)`，不再将未完成用户导向一个没有 Tabs 的独立落地页。
- 首页 Tab 根据首次旅程完成标记选择内容：
  - 无完成标记：显示品牌落地页、帮助、设置和“开启旅程”。
  - 有完成标记：显示长期首页、当前回顾、沟通卡和最近记录。
- “回顾 / 练习 / 我的”在首次旅程前也可正常打开；没有数据时使用现有空状态，不重定向、不假装存在记录。
- 从首页点击“开启旅程”后，仍按原顺序进入成年自我声明、前言和六页正式旅程。
- 18+ 门禁只保护前言与正式旅程内容，不再作为公共 Tabs 的解锁条件。
- 旅程页中保留底部导航；用户切换到其他 Tab 时，当前本机草稿按现有规则保留。

## 首页单屏布局

- 保留右上角“设置”与“帮助”、品牌标识、一张介绍卡和一个主操作，不删除必要文案。
- 移除主操作容器的 `marginTop: "auto"`，避免按钮被强制推向页面底部。
- 保留原有品牌、卡片与模块留白；移除按钮容器的自动撑底后，按窗口宽度、高度和字体缩放选择品牌纵排或中英文横排，不缩小字号、卡片内边距或按钮。
- 品牌页始终禁用垂直滚动和 iOS 垂直回弹；较矮、较窄或放大字体的视口通过品牌重排回收高度。
- 常见小屏、默认字号下，首次可见区必须同时包含品牌、介绍卡、“开启旅程”和底部导航。
- 不通过截断文字、压缩触摸目标或统一收紧视觉间距来达成单屏。

## 状态与错误处理

- 首页加载完成标记时，保持 Tabs 可见，页面内显示现有加载状态。
- 完成标记读取失败时，不隐藏 Tabs；首页显示可重试的本机读取错误。
- 其他 Tabs 的数据加载与错误状态沿用现有实现。
- 正式旅程的未成年阻断、深链保护和草稿持久化规则不变。

## 测试与验收

- 冷启动无完成标记时进入 `(tabs)`，而不是独立 `/journey/welcome`。
- 无完成标记时，四个 Tab 全部可见并可导航。
- 首页无完成标记且没有已确认成年草稿时显示“开启旅程”；存在未完成草稿时沿用原有“继续旅程”，有完成标记时显示长期首页。
- 回顾、练习和我的在无完成标记时不会被 `ShellRouteGate` 送回欢迎页。
- 旅程布局在完成标记缺失、加载中或读取失败时也保持底部导航。
- 首页样式测试锁定原有间距并禁止主操作使用 `marginTop: "auto"`；视口测试覆盖常规纵排与受限视口品牌横排，并断言滚动始终关闭。
- 定向测试、Mobile 全量测试、TypeScript 检查和 ESLint 全部通过。

## 不在范围

- 不改变 18+ 自我声明的文案与判定。
- 不改变六页正式旅程的顺序、数据模型或保存方式。
- 不引入账号、云同步或新的导航库。
- 不将四个 Tab 复制成第二套伪导航。
