# Threat model

## Scope and assets

The protected assets are the model/provider secret, raw practice transcript, saved expression card, course answers/progress, SQLCipher encryption key, random installation token, and prompt/safety-policy text. Availability of the local app and safety-stop behavior are also security properties: an attacker must not turn uncertainty into continued coercive roleplay.

Trust boundaries are: the iOS device and OS keychain; the JavaScript mobile bundle; the network edge and Worker; the model provider; EAS/build service; GitHub and dependency automation; and logs/metrics/error reporting.正文 crosses the device → Worker → provider boundary only for an active request. A provider secret never crosses into the device bundle. The SQLCipher key and installation token remain in device SecureStore.

## Security invariants and response

- A missing database or key, an invalid key, or a SQLCipher open mismatch never triggers automatic deletion. The app preserves all remaining key/database material, fails closed with an explicit recovery-required reason, and waits for a deliberate user recovery or Delete All Data action.
- Schema migrations are append-only, contiguous, transactionally applied one version at a time, and never decrement `user_version`. Concurrent initialization, transactions, close, and deletion share the same per-database coordinator.
- An interrupted Delete All Data operation remains unauthorized and is resumed on the next startup until the pending marker can be cleared after every deletion stage succeeds.
- A malformed or uncertain safety result stops roleplay. Safety policy does not diagnose a condition or make a legal conclusion.
- Rate-limit keys contain only route plus token digest. Raw tokens, request正文, response正文, cards, and provider bodies are not observability inputs.
- If SQLCipher native verification fails, transcript/card saving remains disabled rather than falling back to plaintext. Current transcript stays memory-only.
- Any safety-policy change requires Golden fixture review before changing provider prompts or mobile integration.
- The public landing page is the only journey route available without a persisted adult declaration. Preface, all six formal pages, and resume paths fail closed to public welcome first; only a later explicit Start Journey action opens the declaration gate.
- Optional email authentication is also unavailable before the persisted local adult declaration. It does not unlock local content and is not a substitute for the declaration.
